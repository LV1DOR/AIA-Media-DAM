# Known limits and acceptance boundary

The implemented milestone is an owner-authorized LAN installation with original UI, local accounts and administrator TOTP. It is not an Internet launch or signed marketing UAT.

- Both product URLs and recipient links require AIA network/VPN connectivity and trust in the supplied private CA. No public DNS, corporate SSO tenant or external email was invented.
- Optimized local Chromium layout, keyboard flows and responsive screenshots are covered by the current synthetic browser suite. This is separate from native NAS verification, other browser engines, assistive-technology testing and stakeholder usability acceptance. See the dated review reports for the scope of each check.
- Automated API/native tests use synthetic data and a small existing library. Representative event-scale search, many concurrent users, real WAN throughput and RAW camera samples are not established by those tests. Maxima in validation are limits, not measured scale guarantees.
- Temporary resumable uploads verify names, sizes, order and server offsets. They do not cryptographically identify reselected local files; select the exact original contents. Permanent uploads are whole-file operations, with progress followed by native processing.
- Native large-file finalization has a one-hour bounded request and durable completion intent. A lost response/restart recovers the uniquely named native object by exact size before publishing. Unresolved processing stays unpublished and cleanup retries; a native job that never produces an object needs operator investigation. Abandoned native upload chunks follow the engine's own cleanup policy.
- The current review candidate provides individual originals and a streamed ZIP under one landing link. A ZIP counts as one download start; individual requests, including ranges/retries, each count as one start. ZIPs must restart from the beginning. Revocation cannot recall bytes a recipient already received. This candidate has not been deployed to production.
- Native ResourceSpace expiry has calendar-day granularity; the gateway enforces the exact timestamp and queues native cleanup. DAM approval/access is rechecked for recipient delivery. Native engine URLs and credentials stay server-side.
- Disabling app-managed staff blocks sessions/links immediately, reconciles source shares, then disables the native identity. Backend outages delay native cleanup; failures remain visible and retry. Manually mapped pre-existing source identities are not disabled automatically. App roles are chosen on creation; changing roles requires an operator-reviewed mapping/account change.
- Application administrators and ordinary staff use distinct limited native reviewer/marketing identities. The separate provisioning identity can manage native users and is isolated from ordinary library requests. The original DEV account is preserved for its existing operator use. NAS administrators can still access private storage and credentials.
- Native Gokapi storage encryption is server-managed encryption, not end-to-end encryption. Its keys reside with configuration. Temporary payloads are disposable and excluded from backup; restored links are quarantined.
- Independent encrypted copy/decryption and isolated source/registry restores were tested. Exact runtime images remain NAS-only. DPAPI recovery depends on this Windows user's profile; offsite key escrow, business RPO/RTO and stable human ownership are still outstanding.
- Monitoring writes local/operator evidence; no external alert delivery or on-call destination exists. Backup retention is conservative/manual until business retention and capacity are adopted.
- The GitHub remote is configured for LV1DOR/AIA-Media-DAM and the first local commit is prepared on the development branch. No push, remote CI pass, PR, public deployment or stakeholder signoff is claimed. The workflow performs verification and does not deploy production.
