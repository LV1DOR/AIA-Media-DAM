# Frontend audit and migration baseline

8 November 2026. Branch `frontend/square-ui-redesign`. Existing worktree has no initial commit; implementation files are intent-to-add/untracked. Preserved all files, index state and a pre-redesign source archive under ignored `.local/redesign-baseline/`. No reset/clean/stash or production restart performed.

Baseline: Next 16.4.5, React 19.3.1, TypeScript 7.0.2, pnpm 10.14.0. Both frontends render `packages/ui/src/index.tsx`; its large Workspace component owns auth, server paging, selection and dialogs. Existing 17 security tests pass. Existing gallery is a fixed grid/list; selection clears on page changes, no fullscreen viewer, no native dimensions in the client contract. A large banner consumes gallery space. Current native dialogs and original sidebar are hand-built. Live login and asset-detail screenshots were inspected and saved privately; no baseline Lighthouse/browser-memory pass claimed.

Retain all `/api/auth`, `/library`, `/collections`, `/transfers`, `/admin` contracts and server authorization. Keep upload/resume, MFA, metadata/review, history, recipient password/expiry and revocation behavior. The deployed rollback release is `lan-20261108-e45cafcc`; verify runtime identity again before any frontend rollout. Source/API/registry/Gokapi/DB configuration is outside redesign scope.

Selected components: actual MIT-era Square UI Files source at `192f96aecf599848cad09118c33afe70f1067ae5`, including shadcn/Radix sidebar, sheet, tooltip, dropdown, button/input primitives, plus adapted Files sidebar/header. Current upstream changed to a restrictive custom license in April 2026; do not copy newer source under an MIT label. Preserve the pinned MIT notice. Omit storage charts, mock stores, external avatars, document actions and activity widgets. Use React Photo Album as the single layout engine, the supplied 21st.dev image behavior as its renderer, and lazy-loaded Yet Another React Lightbox.

Integration blocker documented before adapter changes: native `get_resource_data` already returns `thumb_width`/`thumb_height`, but the current Asset contract discards them; the preview route always chooses `scr`. A narrow read-only projection of preview dimensions and validated `thm`/`scr` choice is appropriate for stable, thumbnail-sized galleries. This requires no schema, source plugin, NAS configuration or storage change. Original dimensions must not be fabricated from preview sizes.

Browser QA uses an explicitly selected loopback-only synthetic fixture API and the unchanged frontend HTTP contracts; it never connects to NAS or enters deployment. Production keeps its real API. Capture desktop/tablet/mobile, role denial, loading/error/empty, selection, details, lightbox, review and share interactions. Human acceptance remains distinct from automated checks. Deployment waits for relevant automated and visual acceptance checks, followed by staged native verification under the owner-authorized redesign task. Human production acceptance remains a separate gate.

Additional integration blocker: the current BFF exposes collection list/create only. Required rename and add/remove membership actions cannot function through existing endpoints. A narrow authenticated bridge to installed `save_collection`, `add_resource_to_collection` and `remove_resource_from_collection` is needed. Native bindings are inspected before implementation and remain the write/authorization authority. No private database writes, schema change or source-container modification is needed. This compatible API change is included in the staged review, not silently deployed.

Detail integration blocker: the existing detail response has no collection membership. The installed native `get_resource_collections(ref)` binding is available; add a read-only projection intersected with the caller's existing `get_user_collections` visibility. Never expose other users' private or transfer-managed collection names. Resource access is checked first, and membership lookup failure must not prevent opening/editing the asset.
